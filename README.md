# Moh's P3 curve is a set-theoretic complete intersection

[![Palomar CI](https://github.com/GrgAakash/moh-p3-set-theoretic-complete-intersection/actions/workflows/ci.yml/badge.svg)](https://github.com/GrgAakash/moh-p3-set-theoretic-complete-intersection/actions/workflows/ci.yml)

This repository contains the Lean 4 formalization accompanying the manuscript
*Moh's P3 Curve Is a Global Set-Theoretic Complete Intersection*.

## The result

For a characteristic-zero field `k`, consider

```text
rho : k[x,y,z] → k[t]
x ↦ t^6 + t^31,  y ↦ t^8,  z ↦ t^10.
```

The formalization proves that `ker rho` is generated by

```text
f1 = x^4 - x^2 y^4 z^3 - 2 x y^6 z^2 - 4 xyz - 3 y^3 z^5 + 3 y^3
f2 = x^3 y - x y^5 z^3 - 3 x z^2 - 2 y^7 z^2 + 2 y^2 z
f3 = 2 x^3 z - 3 x^2 y^2 - 2 x y^4 z^4 - y^6 z^3 + y z^2
f4 = x^2 yz - 2 x y^3 - y^5 z^4 + z^3.
```

Write `P = (f1,f2,f3,f4)`.  Define

```text
ell   = 64 x^4 yz^2 - 40 x^3 y^3 z + 72 x y^2 z^3 - 81 y^4 z^2
kappa = -40 x^3 y^2 z^2 + 25 x^2 y^4 z + 36 y^3 z^3

H1 = 81 f4 - 24 x f1 + ell f3
H2 = -12 y f1 + 27 x f2 + kappa f3,
```

and `Q = (H1,H2)`.  Lean proves

```text
ker rho = P,
radical Q = P,
height P = 2,
arithRank P = 2.
```

It also proves the same four statements unconditionally for the induced map
`k[[x,y,z]] → k[[t]]`.  Thus both the affine curve and its formal germ at the
origin are set-theoretic complete intersections cut out by the explicit pair
`H1,H2`.

## Palomar statement surface

The two declarations selected for comparison are

```lean
MohP3.Palomar.global_setTheoretic_completeIntersection
MohP3.Palomar.formalLocal_setTheoretic_completeIntersection
```

[`Challenge.lean`](Challenge.lean) is the short Mathlib-only statement surface.
It writes the parametrizations, four generators, two witnesses, ideals, and
arithmetic rank directly, then leaves exactly two deliberate theorem holes.
[`Solution.lean`](Solution.lean) connects those statements to the completed
proof.  [`comparator.json`](comparator.json) requires both declarations to
match and permits only `propext`, `Quot.sound`, and `Classical.choice`.

## What Lean checks

The proof development establishes more than the two selected conjunctions:

- ten exact polynomial certificate identities yielding `P^2 ⊆ Q ⊆ P`;
- the polynomial kernel computation over `ℚ` and every characteristic-zero
  field, using an explicit eight-generator module argument;
- the power-series kernel computation via a convergent weighted formal
  division algorithm with weights `(6,8,10)`;
- primality and radical equality;
- height two from an explicit strict chain of prime ideals;
- arithmetic rank two from the explicit pair and Krull's height theorem.

The formalization does not formalize the manuscript's Hilbert–Burch
symmetrization narrative as matrix algebra.  It formalizes the resulting
polynomials and verifies the exact certificate identities on which the radical
equality rests.  The Macaulay2 files in [`computations/`](computations/) are
independent computational cross-checks and are not trusted by any Lean proof.

## Reproduce

The project pins Lean 4.28.0 and Mathlib commit
`8f9d9cff6bd728b17a24e163c9402775d9e6a365`.

```bash
lake exe cache get
lake build
ruby scripts/validate-formalization.rb
```

On Linux with Git, Go, Ruby, Rust/Cargo, Python 3, and Landlock support, run
the complete Comparator and NanoDa replay with

```bash
./scripts/verify-comparator.sh
```

GitHub Actions runs the metadata, licence, sandbox-wrapper, Lean-build, and
Comparator checks.

## Verification boundary

The checked Lean theorems are unconditional under `[Field k] [CharZero k]`.
The proof source contains no `sorry`, `admit`, custom axiom, `native_decide`,
or `implemented_by`; the only `sorry`s in the repository are the two deliberate
statement holes in `Challenge.lean`.  The selected Solution declarations use
only `propext`, `Classical.choice`, and `Quot.sound`.

This is a machine-checked formalization, not a substitute for expert
mathematical peer review.  No independent human expert Lean review is claimed.

After a final commit is pinned, a responsible maintainer can use the
[Palomar submission form](https://submit.palomar-registry.org/) with
`comparator.json` at the repository root.
